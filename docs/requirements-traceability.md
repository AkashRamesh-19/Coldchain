## Scope and data-safety notes

- Frontend pages now call the existing authenticated APIs; layout and styling work remains with the frontend owner for any further refinement.
- Known demo shipments are classified through `non_operational_shipments`; source rows and linked operational records are retained.
- The research collection is separate from operational `sensor_readings` and MySQL shipments; research IDs are never mapped to operational IDs.
- Migration `002-shipment-assignments.sql` only adds the assignment table. It does not delete or rewrite existing records.
- Test integration fixtures use isolated test databases and clean up those fixtures; they do not target the configured development database.
- `.env.local` is not included in the audit output or project changes. `.env.example` uses placeholders only.

## Evidence interpretation

The backend integration tests exercise handlers against isolated databases. The two skipped smoke tests require a separately running app plus explicit test URL/bearer configuration. Automated assertions and SQL/API definitions are reproducible evidence; final presentation screenshots should show the running app against its configured database. They are not replaced by build output.
